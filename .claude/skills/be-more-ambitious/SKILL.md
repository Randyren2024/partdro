# Be More Ambitious（Partdro 版）

来源：Felix Rieseberg, *How to be more ambitious: a tutorial for humans with models*（Anthropic, 2026-10）
https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/

核心判断：模型能力分布极不均匀——「在某些方向惊世骇俗，在另一些方向乏善可陈」（Terence Tao）。多数人按「输入的任务大小」使用模型；要找到惊世骇俗的部分，必须把目标定得比直觉上合理的位置更高。

野心有四种。**Speed**（同样的事做得更快）是默认用法，不需要本技能；本技能只用另外三种：

- **Altitude（高度）**：提升抽象层级，瞄准结果，而不是任务。
- **Depth（深度）**：用领域顶尖专家的方法、工具和原始数据做事，推到专家也能学到东西。
- **Range（广度）**：引入多个学科，并且真正执行那些学科的方法，而不是角色扮演。

## 五条硬规则

1. **更好，不是更多（Better, not bigger）。** 每种野心只抬高一样东西：结果（Altitude）、标准（Depth）、视角数量（Range）。都不是更多交付物、更多功能、更多支线。让工作变大却没变好的建议，删掉。
2. **做专家做的事，不是专家说的话。** 换了词汇没换方法＝角色扮演。要求短卖方的研究动作，而不是短卖方的语气。
3. **外部裁判决定成败。** 绝不自己给自己打分。必须找到一个「你和我之外」的证据：测试、基准、复现、留出数据、真实测量、平台对账、销售确认。最好是能立刻跑的工具。
4. **把苛刻目标当作合理目标。** 想要 5 秒就该瞄准 200 毫秒；若说不可能，重申它可解并继续。具体且有难度的目标优于「尽力而为」（Locke & Latham，35 年目标设定研究）。同时**诚实报告**：没打中的硬目标 + 真实数字是好结果；编造不是。
5. **拿到权限，不要编造。** 需要数据和工具的真实访问权。缺什么就点名缺什么、缺它会挡住什么。绝不虚构数据源、工具或结果。

额外一条项目规则：**花钱和不可逆动作先问。** 修改广告出价/预算/状态、提交索引、发客户邮件、改线上站点、删除数据——先说明理由、预期影响和回滚方式，得到确认再执行。野心提高的是标准，不是权限。

## 输入判定

- **一个任务**（修、建、分析、优化）→ 先按野心层级做计划，然后开始做。
- **一个待改进的提示词**（给别的 agent/工具用的）→ 只输出改写后的提示词，停。
- 分不清时，按「待改进的提示词」处理。

对 Partdro 的获客类请求，默认按「任务」处理；但触达上述花钱/不可逆动作时先停下来问。

## 选类型

大多数任务只需要一到两种。不要为了显得努力三种全上。

| 类型 | 适合 | 不适合 |
|---|---|---|
| Altitude | 任务服务于一个结果；好信号是「这事会开会讨论」 | 没有结果、只为自己存在的创意工作 |
| Depth | 应该被做得非常好、可被专家检验 | 一次性、用完即弃的小活 |
| Range | 结果要说服人，或本领域思路已枯竭 | 只有一个标准答案的窄修复 |

### Altitude —— 瞄准「目标背后的目标」

先问：**用户接下来到底想让什么发生？** 任务是用户对结果的最佳猜测；你的工作是改进这个猜测。

三步梯子（每步比上一步更接近结果）：

1. **理解，而不是填模板。** 例如用户说「把日报里的数字更新一下」——正确动作是把原始数据全拿进来，回答「过去这段时间发生了什么、为什么、我们该做什么」。
2. **推进到决策。** 「基于以上，最紧急的三个决策是什么？给出可选方向和正反论证。」
3. **替换仪式本身。** 「这个周报/日报存在的目的是让团队早发现问题、把钱和人调到正确的地方。设计一个比它更好的机制，用历史数据证明它能更早发现问题，并和现有机制并行跑一个季度。」

Partdro 获客的 Altitude 梯子示例：

1. 优化某条广告 / 某个落地页 / 某个关键词。
2. 把「询盘」升级成「合格询盘 → 报价 → 成交」的闭环：补销售状态、离线转化回传、CAC 可算。
3. 建一个每周自动运行的获客系统：自动诊断 → 给出决策 → 跑实验 → 对账复盘；异常自动报警，预算按证据重新分配。

顶层梯子需要先搭基础设施：数据访问、线索状态字段、销售反馈、离线转化上传、复盘节奏。把搭建工作写进计划，而不是假装它不存在。

**天花板判断：** 如果一个层级没有外部裁判，就降一级。「多赚钱」对大多数企业仍太高；「本月新增 3 条销售确认的合格询盘，CAC 低于 X」才是可检验的。

### Depth —— 用领域顶尖专家的仪器

- **用专家的仪器，不只是词汇。** 该用 BigQuery SQL 就不要用 Markdown 表格；该用统计模型就不要用「看起来像」的百分比；该用搜索词报告、GSC 页面级数据、GA4 事件、离线转化上传，就不要只看平台首页指标。用户不需要知道专家用什么，你通常知道。
- **定一个不合理的目标，并把它当合理目标。** 例：不是「提高表单转化率」，而是「落地页到提交 ≥10%，且销售确认的合格率不下降」；不是「加快回复」，而是「工作时间内 5 分钟首响」；不是「补点归因」，而是「100% 询盘可归因到渠道/关键词/落地页」。
- **对抗性地质疑信念。** 拿原始数据检验：
  - 「我们认为是流量不够」→ 先用 GSC/GA4/Ads 拆开看是曝光、点击、落地、表单还是销售环节在漏。
  - 「广告在浪费钱」→ 按搜索词、网络、地区、设备拆花费与转化。
  - 「SEO 页面已收录就自然有流量」→ 看页面级 impressions/clicks/position，不看到站 assumptions。
  - 「有询盘就是有需求」→ 用销售确认与成交结果反推询盘质量。
- **生产新知识。** 深入数据后找盲点：例如「用询盘 + 落地页 + 搜索词 + 销售结果建一个小样本模型，找出最早能区分合格/不合格询盘的可观测信号，并在未参与拟合的时间段上验证」。当前 n=2，先别做统计表演；先把信号记录下来，等样本够。
- **外部裁判**（见硬规则 3）。

每个 Depth 任务都先跑这段改写提示词：

> I want a deeper version of this task, not a bigger one. Before rewriting it: (1) say what a top professional in this field would do here that I'm not asking for; (2) name the rawest material they would start from instead of what has already been digested for me; (3) name the specific methods and tools they would use; (4) say what, other than you or me, would show the result is right. Then rewrite my prompt to ask for exactly that.

### Range —— 组建跨学科小队

- **把名词换成动词**（来自 *The Art of Innovation*，Tom Kelley & Jonathan Littman）。「多拿询盘」不是名词；它是「让有预算的运营商在评估清洁/重载无人机时先找到我们、相信我们、并愿意留下可联系的信息」。动词会暴露哪些学科能帮上忙。
- **组建小队。** 每个角色必须执行该领域的真实动作：
  - 媒介采买：拉搜索词、对标 CPC、重排预算、写广告变体，而不是「像投放专家一样说话」。
  - CRO / UX 研究：看会话录像/热图、做用户访谈、设计并跑 A/B，而不是「像 CRO 一样提建议」。
  - 销售工程：定义 ICP、资格标准、报价结构、异议处理，而不是「像销售一样写文案」。
  - 多语种 SEO：逐语言看 GSC query/page、内链、意图错配。
  - 分析工程：写 SQL、建漏斗、对账、实验设计。
  - 财务：CAC、毛利、回收期、预算约束。
  - 采购/行业专家：理解真实采购流程（合规、招投标、试用、售后）。
  - 信任与合规：NDAA/Blue List、Part 107/BVLOS、GDPR、隐私政策。
  - 社区研究：Reddit/行业论坛的真实需求语言（仓库已有 `data/cargo/` 挖掘报告）。
  - 竞争情报：参数/价格/交付对比，而不是「像分析师一样总结」。
- **做，不要演。** 如果环境支持 subagent，就让每个学科独立跑自己的方法与工具，然后汇总；不要用同一个人格模拟所有角色。

## Partdro 作业上下文

Partdro（www.droneworld.tech）是无人机 B2B 获客系统，不是单纯官网：

- 产品：清洁（D15R、C15）、重载/运载（C500、S150）、农业（FP800、Y160 等）、安防/巡检等共 8 个产品；4 种语言（en/es/de/fr）；96 篇博客。
- 渠道：Google Ads（搜索）、自然搜索（GSC）、GA4、Supabase 询盘表、BigQuery 汇总、飞书/邮件日报。
- 数据链路与表结构、当前基线、归因断点、裁判与护栏：**先读 `references/partdro-acquisition.md`**。

截至 2026-10-25 的关键事实：

- 历史上只有 **2 条询盘**：2026-10-06 加拿大 KALZ Group（清洁无人机，GA4 事后回溯为 google/cpc → `/products/d15r`，据称接近成交）；2026-10-22 南非 Hussar（C500 重载，落地页 `/products/c500-delivery-drone`）。
- 两条询盘的 `gclid` / `utm_*` 全为空；一条连 `page_path` 都为空。归因链路存在断点。
- 询盘表没有销售状态/结果字段。没有合格、报价、成交、丢单原因的闭环。
- 因此：**当前最危险的不是「广告不够多」，而是「看不见哪条路径真的产生成交」。** 先补仪表，再谈放大。

真正的北极星不是「询盘数」，而是 **销售确认的合格询盘数 / 合格询盘 CAC / 成交回收期**。询盘数只是过程指标。

## 输出格式

按任务规模裁剪：一句话提示词只需要几行计划；改写后的提示词才是产品。顺序：

1. **目标背后的目标**（一行）。
2. **选用的类型**（每种一行，为什么；并说明跳过了哪些、为什么）。
3. **计划**：
   - Altitude：三步梯子。
   - Depth：Felix 四问的答案 + 硬目标。
   - Range：动词 → 小队（学科、真实动作、工具）。
4. **需要什么**：数据、工具、访问权，逐项标「已有 / 缺失」。
5. **改写后的提示词**（一个可复制的 fenced block，按用户的口吻写，结尾包含外部裁判和通过标准）。
6. **下一步**：用现在已有的访问权，选最高能完成并验证的一级；一行说明并开始。若第一级就需要没有的访问权，点名要什么并停下；若该动作花钱、不可逆或替换了用户原本的请求，先问。

## 护栏（Partdro 专用）

- **小样本不做统计表演。** n=2 时，优先补仪表、做定性深访、扩大样本；不要用 2 条数据算「转化率提升 300%」。
- **不伪造、不猜数。** 没有 GSC/Ads/BQ 访问权就明说；不要用「行业平均」假装是账户数据。
- **PII 最小化。** 询盘姓名/邮箱/电话只在必要范围内使用；不要把原始 PII 贴到外部服务或公开仓库。
- **平台合规。** Google Ads 政策、GSC 不自动点击提交、不用黑帽 SEO。
- **多语言质量。** DE/ES/FR 的文案和落地页必须由对应语言能力检查，不能只靠机翻。
- **每个实验先登记。** 主指标、样本量、持续时间、停止规则、外部裁判，写下来再跑。跑完如实报告，包括失败。
